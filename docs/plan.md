# RaiseLine 計画書

2026-10-29 作成、2026-10-30 更新。要件は [`requirements.md`](./requirements.md) を参照。

## 概要

RaiseLine は旧Twitter風のテキストSNS。140文字の投稿を書いて、みんなの投稿を新しい順に読める。プログラミング学習の一環として、フロントエンド・バックエンド・データベースの3層構成で作る。

## 主な機能

| フェーズ | 機能 |
| --- | --- |
| 1（MVP） | ユーザー登録・ログイン（Cookie セッション）、テキスト投稿（140字）・削除、全体タイムライン（もっと見る）、ユーザーページ、投稿日時の相対表示、アカウント設定（表示名・アイコンの変更、メール・パスワード変更） |
| 2 | ユーザー検索、コメント、いいね（数の表示つき） |
| 3 | フォロー/フォロー解除、ホームタイムライン（「ホーム / みんな」タブ）、自己紹介 |
| 4 | リポスト、画像添付（1枚、AWS では S3） |

### X/Twitter との違い

- 投稿は140字（絵文字も1字として数える）
- インプレッション数・おすすめ・トレンドは出さない
- 投稿の編集、DM、通知は作らない

## 技術スタック

| レイヤー | 主要技術 |
| --- | --- |
| フロントエンド | React 19 + TypeScript + Vite + React Router（UI ライブラリは使わず CSS を自分で書く） |
| バックエンド | Java 25 + Spring Boot 4.1 + Maven（Spring Data JPA、BCrypt） |
| データベース | MySQL 8.4（ローカルは Docker、AWS は RDS） |
| テスト | JUnit 5 + MockMvc（テスト用 DB は H2）、フロントは Vitest |
| インフラ | AWS（EC2 + RDS、画像を入れるフェーズ4で S3）+ Terraform |

- 画面と API は同じオリジンで配信する（ビルドした React を Spring Boot の静的ファイルとして同梱）。ログインの Cookie をそのまま使えるので、JWT や CORS の設定が要らない
- 手本: バックエンドは `task-manager-app`（Spring Boot）、デプロイは `finance-manager-app`（EC2 + RDS）

## プロジェクト構成

```
sns-app/
├── prototype/               # 画面のプロトタイプ（HTML/CSS/JS、ダミーデータ）
├── frontend/                # フロントエンド（React + Vite）
├── backend/                 # バックエンド（Spring Boot）
├── infra/terraform/         # インフラ（AWS / Terraform）
├── docs/
│   ├── requirements.md      # 要件定義書
│   └── plan.md              # 計画書（このファイル）
└── docker-compose.yml       # ローカルの MySQL（ポート 3307）
```

## デザイン方針

- X/Twitter 風のシンプルなデザイン
- カラー: 白背景、青のアクセントカラー。ダークモードにも切り替えられる
- 最大幅 600px の中央寄せレイアウト（スマホ幅ではそのまま全幅）
- 共通ヘッダーを上部に固定（ロゴ、自分のユーザーページ、設定、ログアウト）
- 投稿欄はタイムラインの一番上。残り文字数を表示し、超えたら投稿ボタンを押せない
- エラーは画面上部の赤いバナーで表示

## 検証方法

| 対象 | 方法 |
| --- | --- |
| バックエンド | `mvn test`。各 API の正常系とエラー（400/401/404/409/429）、140字の境界値（絵文字を含む）、「もっと見る」で投稿の重複・欠落がないこと、他人の投稿を消せないこと |
| MySQL | `docker compose up -d` → バックエンドを起動し、絵文字入りの投稿とユーザー名の大文字・小文字の重複チェックを確認 |
| プロトタイプ | `prototype/index.html` をブラウザで直接開き、全画面への遷移と、投稿・削除の確認・もっと見る・残り文字数・エラー表示の動きを確認 |
| React | 2人のテストユーザーで、登録 → 投稿 → 相手のタイムラインに出る → ユーザーページ → 削除、を PC の Chrome とスマホ幅で確認 |
| 性能 | タイムラインの1ページが 300ms 以内 |
